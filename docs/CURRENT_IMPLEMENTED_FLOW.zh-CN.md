# Mimosa 当前实现流程（协议 v14）

本文只描述当前代码已经实现的行为。

## 1. 入会与自动感知

房间 ID 默认留空，不再内置固定会议室。研究者为每组分配不同房间 ID，成员输入相同编号即可进入彼此隔离的会议，从而支持同一部署同时开展多组实验。JaaS App ID 仍由部署配置提供，它是会议服务的项目标识，不是实验房间 ID，也不需要参与者填写。

页面提供完整中文和英文运行版本。右上角可随时切换语言，也可通过 `?lang=en` 直接进入英文版本；会议、参与者互动、研究观察端、种子暂存区、日志和无障碍标签都会随语言切换，而不是只为论文截图替换文案。

自动感知遵循“先有讨论，再识别讨论后的沉默”：加入房间后若从未检测到任何成员发言，系统不会因会前安静而触发；一旦房间出现过有效发言，就以最后一次语音活动结束为起点。此后只要整个房间连续 8 秒没有检测到新的语音活动，就创建候选沉默。发言者说完后是否闭麦、其他成员分别处于开麦还是闭麦状态，都不改变这一判定。

- 所有人以普通成员身份加入，角色只在单次沉默时刻中临时产生。
- 入会后，浏览器请求麦克风权限，在本地判断“正在说话/停止说话”。
- 系统不上传、保存或广播音频，只同步布尔语音活动信号。
- 若权限不可用，会议仍可正常使用，并可通过“模拟检测到一段持续沉默”完成实验校准。
- 房间内代码自动选择一个客户端维护共享计时。它不是主持人，也不会改变该成员的界面或权限。

## 2. 三种进入方式

### 2.1 自动检测

系统观察到至少一次发言后，如果整个房间连续约 8 秒没有语音活动，就创建一个候选沉默：

1. 所有人私下看到同一份角色确认。
2. 含羞草尚不出现，页面只保留幼苗。
3. 成员可选“我正在等待回应 / 我可能会回应 / 暂时不需要 Mimosa”。
4. 12 秒内无人认领等待者，提示自然收起。
5. 候选阶段有人重新开口，提示立即自然收起。
6. 第一位成功认领“我正在等待回应”的成员建立本轮接收通道，候选计时随即取消，含羞草开始生长。

自动检测只识别持续安静，不判断这是否一定是开放问题，也不推断谁是提问者。角色和需求由成员自己表达。

### 2.2 手动模拟检测

“模拟检测到一段持续沉默”直接进入同样的角色确认流程，用于实验校准、麦克风权限失败和演示。后续 12 秒认领、自动退场和角色建立规则与自动检测相同。

### 2.3 手动标记开放问题

任何成员都可填写问题摘要并点击“标记为开放问题”。发起者立即成为本轮等待者，其他成员进入可能回应路径，含羞草直接生长。这条路径适用于成员明确知道自己刚提出开放问题的情况。

## 3. 角色确认与隐私

- **我正在等待回应**：申请接收匿名线索，并可补充问题摘要。
- **我可能会回应**：问题被认领后进入低压力回应界面。
- **暂时不需要 Mimosa**：选择仅保留在本地，不发送给任何成员。
- 多人同时认领时只接受最先抵达的申请。
- 等待者身份需要建立定向消息通道；其他两类选择不公开、不计数。
- 普通界面没有“主持人撤销”或“全局撤销”按钮。误判通过 12 秒无人认领或重新开口自动消退。

## 4. 正式沉默支持

### 等待者

- 看到匿名回应总数及三类精确汇总：需要一点时间、正在确认、有社交压力。
- 看不到回应者与选择之间的对应关系。
- 可选择“不急，慢慢想 / 大家都可以补充 / 稍后再回到”。

### 可能回应者

- 选择“需要一点时间”或“正在确认”后，再用阳光或浇水表达。
- 选择“有社交压力”后以云层表达。
- 语义线索只定向送达等待者；全房间只看到匿名环境变化。
- 每位成员每轮发送一次，但可从“暂时不需要”重新加入。

### 植物和环境

- 正式轮次开始时，幼苗自然生长为含羞草。
- 生长过程稳定后，叶片立即开始缓慢、连续地合拢，不再额外等待 12 秒。这个变化表达沉默中的不确定性正在逐渐累积，不是对成员的倒计时或惩罚。
- 活跃含羞草保持幅度很小的有机摆动，让植物具有生命感，但不使用强烈摇晃、闪烁或其他催促式动效。
- 场景采用透明覆盖层并避开会议底部工具栏；植物附近的说明改为“小助手”式对话气泡，随语言和植物状态自然变化。
- 阳光、浇水和云层改变共享环境；等待者的关怀动作改变植物状态。
- “稍后再回到”把植物收成种子，问题进入房间共享暂存区，并在各客户端按 App ID 与房间名本地持久化。
- 原认领者可直接编辑并重新带回问题；考虑到重新进入会议后 Jitsi 临时参与者 ID 会变化，其他当前成员也可认领、编辑并重新带回，或通过二次确认将已失效问题移出暂存区。
- 移除操作广播给同房间成员并写入匿名事件日志；本地删除记录会阻止旧缓存快照把已删问题重新带回。

## 5. 讨论恢复

- 正式轮次开始至少 3 秒后，系统若检测到持续约 2 秒的语音活动，只向等待者显示“讨论似乎重新接上了”的确认卡。
- 系统不会自动结束正式轮次。
- 等待者可确认“结束本轮”，也可选择“继续保留”。
- 手动的“讨论已经恢复，结束本轮”始终保留，供漏检、静音和实验操作使用。

## 6. 多人、离会与恢复

- Mimosa 不限制为四名参与者；所有参与者集合、匿名计数、状态广播和日志期望数均按当前房间动态计算。
- 研究观察员通过独立身份消息被全房间识别，不进入实验参与人数、语音活动集合或协调者选举。
- 参与者加入或离开时，语音活动集合和自动计时会随之更新。
- 维护共享计时的客户端离开后，剩余客户端自动接管候选的剩余时间。
- 正式等待者离开时，本轮安全收束，避免其他成员继续向失效身份发送私密消息。
- 后加入者可恢复候选角色确认或正式公开状态，但不会获得此前的私密线索和发送者信息。
- 暂存问题按 JaaS App ID 与房间名保存在等待者浏览器本机，刷新后仍可编辑并带回。

## 7. 实验日志

- 每个浏览器会话生成匿名 session ID 与参与者编号。
- 本地记录连接、感知状态、候选创建/取消原因、角色认领、匿名线索、关怀行动、恢复建议、离会与轮次结束等事件。
- 日志保存在本机；研究观察端可向所有在线参与者请求日志分片并下载聚合 JSON，本地导出作为备用。
- 导出文件包含协议版本、8 秒沉默阈值、12 秒角色窗口、12 秒叶片合拢阈值和感知模式。

## 8. 研究观察端

- 使用 `?research=1` 进入同一房间，默认保持闭麦。
- 只能观察共享状态、查看匿名分类汇总、标记实验开始/结束、撤销误触发和请求日志。
- 不能认领等待者、发送匿名回应、执行关怀动作或影响自动沉默检测。
- 观察端人数与实验参与人数分开显示。

## 9. 当前技术边界

- 当前 V1 识别的是房间语音活动，不识别问句语义。
- 浏览器本地 VAD 会受到麦克风、回声和环境噪声影响，因此保留手动标记与模拟入口。
- 系统一次只支持一个活跃沉默时刻。
- `换一种方式问`保留在内部协议兼容层，但不出现在当前正式界面。
