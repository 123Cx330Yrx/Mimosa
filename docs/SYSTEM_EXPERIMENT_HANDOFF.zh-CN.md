# Mimosa 系统设计与实验交接手册

版本：v14-bilingual  
交付日期：2026-07-31

## 1. 系统定位

Mimosa 是嵌入网页会议的轻量双向互动系统。它不推断“谁消极、谁走神、谁正在思考”，只检测会议中可能需要支持的持续安静，并让成员私下认领当下位置。系统通过“共同察觉—自我表达—关怀回应—互动修复”的闭环，降低开放问题无人回应时的误解和压力。

含羞草代表一次需要被共同照顾的沉默时刻，不代表某个具体成员。个人回应默认匿名；等待回应者可以看到三类回应的精确数量，但看不到成员身份。

## 2. 技术构成

- React + TypeScript + Vite：Mimosa 页面、状态机、动效和本地日志。
- JaaS/Jitsi IFrame API：网页音视频会议、参与者身份、定向消息和广播消息。
- Web Audio 本地活动检测：仅在本机且本人未闭麦时判断“正在发言/停止发言”。
- `localStorage`/`sessionStorage`：保存本机匿名事件日志、会话编号和暂存问题。

系统不录音、不转写、不上传音频，也不识别发言内容。房间中只同步布尔活动状态、Mimosa 协议消息和共享视觉状态。

## 3. 三种访问模式

### 普通参与模式

链接不带参数，例如 `https://mimosa-srtp.com/`。页面默认不填写房间 ID，由成员输入研究者分配的编号；不同编号进入相互隔离的会议。仅显示会议和 Mimosa 互动，不显示 App ID、自动感知开关、开发校准、日志清空或实验诊断信息。

### 正式实验模式

使用 `https://mimosa-srtp.com/?study=1&room=组别编号`。交互与普通模式相同，另提供折叠的“实验记录”，只包含本机匿名编号、已记录事件数和日志导出。英文实验链接增加 `&lang=en`。正式实验推荐所有参与者使用这一入口。

### 研究观察模式

使用 `https://mimosa-srtp.com/?research=1&room=组别编号`。研究者进入同一会议进行观察和实验调控，但不属于实验参与者：不参与角色认领、匿名回应、沉默检测和房间协调者选举。观察端可标记实验开始/结束、撤销一次误触发、查看匿名聚合数据，并向所有在线参与者集中请求和下载日志。英文观察端增加 `&lang=en`。JaaS App ID 已由部署配置自动填充，任何使用者均无需输入。

### 中英文版本

系统不是单独生成一套英文截图，而是在同一部署中提供完整的中英文运行版本。入会页、互动流程、植物小助手、种子暂存、观察端和日志相关界面都会切换语言。右上角可在会议前后切换，`?lang=en` 可固定英文入口。语言与房间 ID 相互独立，因此同一组也可以分别检查中英文界面。

## 4. 完整交互流程

### 4.1 入会

所有成员输入相同房间 ID 和各自显示名进入会议。房间 ID 默认留空，研究者在实验开始前按组分配，例如 `G01-task1`、`G02-task1`；多组同时实验时不得共用同一编号。系统根据房间成员动态扩展，不设 Mimosa 侧的四人上限。四名参与者只是推荐实验基线；第 5、6 位及更多成员使用完全相同的角色确认、匿名回应、状态同步和日志机制。研究观察员另计，不进入参与人数。

### 4.2 两种触发方式

**手动触发：**任何成员认为自己提出了开放问题并正在等待回应时，可填写问题摘要并点击“标记为开放问题”。该成员直接成为本轮等待回应者。

**半自动触发：**系统至少观察到一次真实的未闭麦发言后，若全房间连续安静约 8 秒，弹出私密角色确认。系统只判断“出现持续安静”，不判断谁提出了问题。

### 4.3 私密角色确认

每位成员在自己的页面选择：

- 我正在等待回应：认领等待者位置，可补充问题摘要；
- 我可能会回应：等待问题被认领后进入低压力回应入口；
- 这次我先不参与：仅收起自己的入口，不取消其他人的 Mimosa。

第一个成功认领等待者的成员成为本轮等待者。如果 12 秒内无人认领，提示自然退场并进入冷却；系统不会在同一段持续安静中反复弹出，必须先发生新的真实发言，才可能再次触发。

### 4.4 正式沉默时刻

角色建立后，幼苗自然生长为舒展的含羞草。生长稳定后叶片立即开始缓慢、连续地合拢，不再额外等待一个 12 秒阈值。合拢表达沉默中的不确定性正在累积，而不是倒计时或对任何人的惩罚。植物在活动期间保持轻微的自然摆动；透明场景层避开会议工具栏，旁边由中英文“小助手”对话气泡说明当前变化。

### 4.5 回应者的匿名线索

回应者选择“需要一点时间”“正在确认”或“有社交压力”。前两类随后可选择阳光或浇水作为环境动作；社交压力以云层表达。环境变化对全体可见，选择类别只定向发送给等待者，姓名不公开。

多人可以同时回应。环境采用聚合场景，不使用后到回应覆盖先到回应的逻辑。

### 4.6 等待者的关怀动作

等待者看到三类匿名回应的精确数量，但不知道具体是谁，然后选择：

- 不急，慢慢想：留出时间；
- 大家都可以补充：降低单人回应压力；
- 稍后再回到：将问题收成种子并暂存；
- 讨论已经恢复，结束本轮：确认互动已重新接上。

### 4.7 讨论恢复与结束

正式轮次中检测到持续语音活动时，系统只向等待者提示讨论可能恢复，由等待者确认结束或继续保留。系统不会仅因检测到声音擅自结束本轮。

结束时，含羞草自然退回土壤并重新抽出幼苗。若暂存，种子暂存区对全体成员可见。原认领者可直接编辑并重新带回；考虑到重新打开网页后 Jitsi 临时参与者 ID 会变化，其他当前成员也可以认领、编辑并重新带回，或通过二次确认清理已经失效、误存或用于测试的问题。删除会同步到同房间在线成员并记录匿名事件，晚加入成员不会重新收到已经删除的种子。

种子之所以会在刷新后继续出现，不是系统内置了示例问题，而是客户端按“JaaS App ID + 房间名”把共享暂存区保存到了浏览器 `localStorage`。这保证正式实验中刷新页面不会丢失待讨论问题。需要清理时，应使用种子卡片中的“移出暂存区”，不要通过清空全部浏览器数据处理。

## 5. 自动感知边界

自动感知不是“进入房间后一直倒计时”，而是“先观察到真实讨论，再判断讨论后的停顿”。房间尚未出现过任何语音活动时不会触发，避免会前等待、设备准备和成员尚未到齐时误报。一旦检测到过发言，就以最后一次语音活动结束为起点；此后只要全房间连续 8 秒没有新的语音活动便触发。发言者说完后是否闭麦、其他成员各自处于开麦还是闭麦状态，都不构成额外条件。

- “本地”指每台电脑只读取自己的麦克风输入活动。
- 只有 Jitsi 中本人未闭麦时，本机才参与房间活动判断。
- 闭麦时环境声不应被视为该成员在会议中发言。
- 房间只收到布尔活动信号，不收到音频内容。
- 自动触发失败时仍可手动标记开放问题，因此研究重点不是语音识别准确率。

## 6. 日志结构

每台电脑独立记录事件：

| 字段 | 含义 |
|---|---|
| `sessionId` | 当前标签页会话标识 |
| `participantPseudonym` | 随机匿名编号 |
| `sequence` | 本机事件顺序 |
| `at` | ISO 时间戳 |
| `type` | 事件类型 |
| `momentId` | 沉默轮次标识，可跨参与者合并 |
| `details` | 事件附加信息 |

日志覆盖入会、候选沉默、角色认领、正式轮次、匿名线索、环境动作、关怀动作、叶片合拢、讨论恢复、暂存/恢复、结束及感知异常。

## 7. 正式实验收数

系统采用“参与者本地记录、研究观察端按需汇总”的方式，不需要另建日志服务器。JaaS 不保存 Mimosa 研究日志；每台参与者浏览器继续保存匿名本地事件，实验结束时由研究观察端通过房间数据通道发起收集，并下载一个聚合 JSON。参与者手动导出保留为连接异常时的备用方案。

### 实验前

1. 为该组确定唯一房间 ID 和任务编号。
2. 所有实验参与者使用带相同 `room=` 的 `?study=1` 链接；一名研究者使用带相同 `room=` 的 `?research=1` 链接进入同一房间。
3. 观察端确认“实验参与者”人数正确，观察员未计入其中。
4. 点击“标记实验开始”，再开始任务。
5. 若建立真实参与者与匿名编号对应表，应单独加密保存；不需要重识别时不要建立。

### 实验结束

1. 研究者点击“标记实验结束”。
2. 点击“向参与者收集日志”，等待计数达到“已收到/在线参与者”一致。
3. 点击“下载汇总日志”，得到包含各匿名参与者日志的聚合 JSON。
4. 若个别参与者未回传，则由该参与者展开“实验记录”并手动导出本地 JSON 作为补充。
5. 将聚合文件与备用文件保存到仅研究团队可访问的位置。

### 合并与质量检查

- 以 `momentId` 合并同一轮各参与者事件；
- 以 `at` 排序还原时间线；
- 检查 `sequence` 是否连续；
- 检查感知不可用、成员离开和状态恢复事件；
- 将观察笔记按时间对齐；
- 不从匿名反馈反推回应者身份。

## 8. 可计算的过程指标

- 沉默候选次数及取消原因；
- 候选到角色认领的时长；
- 正式轮次到首个匿名回应的时长；
- 每轮回应数及类别分布；
- 等待者关怀动作；
- 暂存数量和重新带回比例；
- 讨论恢复提示到结束的时长；
- 自动触发无人认领或因新发言退出的次数。

这些只是行为过程证据。心理压力、误解、社会联结、关怀觉察和可接受性仍需问卷与访谈。

## 9. App ID 与账号归属

当前交付包内置现有测试 App ID，参与者无需填写。App ID 是公开项目标识，不是密钥。

正式实验建议使用由项目公共邮箱、组长或实验室共同管理的 JaaS 项目，并在构建时配置 `VITE_JAAS_APP_ID=团队AppID`。

不得把 JWT 私钥、API Secret 或私钥文件写进前端、压缩包或代码仓库。未来若鉴权，应由可信后端签发短期 JWT。

## 10. 当前限制

- 集中日志请求依赖参与者在实验结束时仍保持页面在线；离线或刷新后的参与者需使用本地备用导出；
- 暂存问题在房间内同步并在各客户端本地持久化；清空浏览器数据或所有成员离开后仍需另行备份；
- 自动感知受浏览器权限、静音状态和设备差异影响；
- 公共 JaaS 配额受项目账号影响；
- 这是研究原型，不是生产级会议平台。

## 11. 多人验收清单

1. 至少四名参与者和一名研究观察员进入同一房间；参与人数只计算参与者。
2. 手动开放问题可进入正式轮次。
3. 真实发言后安静约 8 秒，四人收到角色确认。
4. 一人认领等待者，其他人角色互不覆盖。
5. 三名及更多回应者提交线索，等待者的匿名总数和分类数随人数动态增长。
6. 阳光、浇水、云层协调共存并自然进退。
7. 等待者关怀动作全员同步。
8. “这次我先不参与”只影响本机。
9. 暂存问题可编辑并恢复。
10. 讨论恢复由等待者确认结束。
11. 第 5、6 位成员中途加入后可恢复公开状态并参与后续互动。
12. 研究观察端可集中收齐所有在线参与者日志；本地导出可作为备用。

## 12. 系统如何部署和交给参与者

正式实验采用“腾讯云集中部署、参与者浏览器访问”的方式。研究团队将静态部署包发布到腾讯云 EdgeOne Makers/Pages，并绑定自定义 HTTPS 域名；参与者不安装插件、不运行源码，也不需要 Node.js。

当前正式域名为 `https://mimosa-srtp.com`：

- 普通演示：`https://mimosa-srtp.com/`
- 中文正式实验：`https://mimosa-srtp.com/?study=1&room=G03-task1`
- 英文正式实验：`https://mimosa-srtp.com/?study=1&room=G03-task1&lang=en`
- 中文研究观察：`https://mimosa-srtp.com/?research=1&room=G03-task1`
- 英文研究观察：`https://mimosa-srtp.com/?research=1&room=G03-task1&lang=en`

实验负责人提前创建一条约定，而不是在服务器后台创建房间：为每组指定一个不重复的房间 ID，例如 `G03-task1`，然后把带该 `room=` 的正式实验链接发给参与者，把带相同 `room=` 的研究观察链接发给研究者。JaaS 会在首位成员进入时建立该会议房间。若不在链接中预填 `room=`，入会页会保持空白，由成员自行输入。

腾讯云生成的“预览”地址仅用于部署验收，可能是短期链接，不得作为正式实验入口。自定义域名必须关联生产环境，并完成 DNS 与 HTTPS 配置后再交给参与者。若域名尚未完成中国大陆 ICP 备案，EdgeOne 项目不得选择包含中国大陆的加速区域。

截至 2026-07-25，普通入口、正式实验入口和研究排障入口均已通过线上 HTTP 200 可访问性检查。主交接工作因此以实验使用、日志收集和后续版本更新为主；首次绑定域名的完整步骤仅保留在 `TENCENT_CLOUD_DEPLOYMENT.zh-CN.md` 作为部署附录。

## 13. 参与者操作教学

1. 打开实验负责人发送的 `?study=1` 链接。
2. 核对链接中已经预填的房间 ID，或输入负责人分配的房间 ID 和实验显示名。
3. 点击“进入会议”，授权摄像头和麦克风。
4. 正常完成协作任务。
5. 出现角色确认时，只描述自己当前的位置。
6. 成为回应者后，可以发送匿名需要和环境动作。
7. 成为等待者后，根据匿名汇总选择关怀推进方式。
8. 实验结束后不要关闭页面，先导出“实验记录”。

## 14. 实验负责人当场操作

### 开始前

- 记录组号、实验条件、任务、房间 ID、语言版本和开始时间；
- 确认参与人数符合实验设计（推荐至少四人），研究观察员单独显示；
- 确认每人使用 `?study=1`；
- 确认事件数在入会后增加；
- 只让指定研究者进入 `?research=1`，参与者不得使用该入口；
- 研究者保持闭麦，不参与任务讨论。

### 进行中

- 不替参与者选择角色或回应；
- 仅在明确误触发时使用“撤销本次误触发”，并记录原因；
- 记录网络中断、设备权限、误触发和成员离开等异常及时间；
- 系统未自动触发但确有开放问题时，允许提出问题的成员手动标记。

### 结束后

- 在观察端标记实验结束并请求日志；
- 核对汇总计数等于在线参与人数；
- 下载聚合 JSON；对未回传者收取本地备用日志；
- 再进行问卷和访谈；
- 不从匿名反馈倒推具体回应者。

## 15. 部署更新的最短步骤

1. 打开腾讯云原 Mimosa 项目。
2. 上传腾讯云兼容包 `mimosa-cloud.zip`；包内 `index.html` 位于根目录，且所有文件名均为 ASCII。
3. 在预览地址完成至少四名参与者加一名观察员的验收，并额外测试第 5、6 位成员加入。
4. 发布为生产部署。
5. 确认自定义域名 `mimosa-srtp.com` 仍关联生产环境，DNS CNAME 与 HTTPS 证书状态正常。
6. 分别检查中文、英文的参与者与研究观察链接，并确认不同 `room=` 不会相互看见。

首次部署时，应在 EdgeOne Makers 中选择“创建项目 → 直接上传”，项目名使用 `mimosa-srtp`。按照控制台给出的值完成域名归属验证和 CNAME 配置，不自行推测记录值；再为 `mimosa-srtp.com` 配置 HTTPS 证书并开启强制 HTTPS。部署包根目录直接包含 `index.html`、CSS、JavaScript 与 SVG 文件，不要上传完整源码包、`node_modules` 或外层套有目录的 ZIP。详细步骤见 `TENCENT_CLOUD_DEPLOYMENT.zh-CN.md`。
