# Mimosa 腾讯云部署、运行与实验操作

正式域名：`https://mimosa-srtp.com`  
腾讯云项目名：`mimosa-srtp`  
推荐托管：腾讯云 EdgeOne Makers 直接上传  
音视频服务：JaaS/Jitsi

## 1. 运行架构

正式实验采用“腾讯云集中部署、参与者浏览器访问”的方式：

```text
研究团队构建并上传静态部署包
            ↓
腾讯云 EdgeOne Makers 托管网页与 HTTPS
            ↓
参与者访问 https://mimosa-srtp.com/?study=1&room=研究者分配的房间ID
            ↓
JaaS 提供音视频会议和客户端间实时消息
```

参与者不安装浏览器插件、不运行源码，也不需要 Node.js。腾讯云只托管网页，JaaS 负责会议。Mimosa 研究日志保存在参与者浏览器本机，实验结束时由研究观察端集中请求并下载；本地单独导出作为故障备用。

## 2. 部署前准备

使用交付目录中的腾讯云兼容包：

```text
mimosa-cloud.zip
```

不要上传旧版 `mimosa-tencent-deploy.zip`、完整源码、`node_modules` 或整个交接包。兼容包内没有文件夹、中文文件名或特殊字符：

```text
index.html
favicon.svg
icons.svg
index-xxxxxxxx.css
index-xxxxxxxx.js
```

`index.html` 必须位于 ZIP 最外层。如果腾讯云提示文件名包含 `\ / : * ? " < > |`，先删除页面中已经选中的旧文件、刷新创建页面，然后只选择 `mimosa-cloud.zip`。

当前交付包已内置测试用 JaaS App ID，参与者无需填写。App ID 是公开项目标识，不是密钥；API Secret、JWT 私钥和私钥文件不得放入前端或部署包。

网页不再内置固定房间 ID。JaaS App ID 只决定使用哪个会议服务项目，房间 ID 才决定参会者进入哪一间会议。研究者应为并行实验分配不同编号；参与者可在入会页填写，也可由研究者通过链接的 `room=` 参数预填。

系统提供完整中英文运行版本：默认中文，链接增加 `lang=en` 后为英文；页面右上角也可切换语言。两种语言使用同一部署和同一套协议，不是截图专用页面。

## 3. 第一次创建 EdgeOne 项目

1. 登录腾讯云控制台，搜索并进入 **EdgeOne Makers**。
2. 选择 **创建项目 → 直接上传**，不要选择 Git 导入。
3. 项目名称填写 `mimosa-srtp`。
4. 选择加速区域：
   - 域名已完成中国大陆 ICP 备案：可选“全球可用区（含中国大陆）”；
   - 域名未备案：选择不包含中国大陆的全球区域。
5. 上传 `mimosa-cloud.zip`。
6. 点击 **开始部署**，等待状态变为部署成功。

部署成功后，先打开腾讯云提供的默认地址检查页面、会议和动画。控制台中的“预览”地址可能是短期链接，只用于验收，不应发给正式实验参与者。

推荐在正式实验前生成每组专属链接：

```text
中文参与者：https://mimosa-srtp.com/?study=1&room=G01-task1
英文参与者：https://mimosa-srtp.com/?study=1&room=G01-task1&lang=en
中文观察端：https://mimosa-srtp.com/?research=1&room=G01-task1
英文观察端：https://mimosa-srtp.com/?research=1&room=G01-task1&lang=en
```

多组同时开展时，把 `G01-task1` 分别换成唯一编号。不要让两个实验组使用同一房间 ID。

## 4. 绑定 `mimosa-srtp.com`

### 4.1 添加域名

1. 进入 `mimosa-srtp` 项目。
2. 打开 **域名管理 → 添加自定义域名**。
3. 输入 `mimosa-srtp.com`。
4. 关联环境选择 **生产环境 / Production**。
5. 如需备用入口，可再添加 `www.mimosa-srtp.com`。

### 4.2 验证域名归属

腾讯云会显示一条 TXT 或 CNAME 验证记录。进入域名当前使用的 DNS 服务商；如果域名使用腾讯云 DNSPod，则进入：

```text
腾讯云控制台 → DNSPod / DNS 解析 → mimosa-srtp.com → 添加记录
```

严格复制 Makers 控制台显示的记录类型、主机记录和记录值，TTL 使用默认值。不要自行推测验证记录。添加后返回 Makers 点击验证。

### 4.3 配置正式 CNAME

验证通过后，Makers 会提供一个正式 CNAME 目标。为根域名添加：

```text
记录类型：CNAME
主机记录：@
记录值：Makers 控制台实际给出的 CNAME
线路类型：默认
TTL：默认
```

如添加 `www.mimosa-srtp.com`，再为主机记录 `www` 添加控制台给出的对应 CNAME。

如果提示记录冲突，先截图备份原记录，再检查同一个主机记录是否已有 A、AAAA 或 CNAME。确认旧记录不再使用后再删除冲突记录。不得删除 NS 或 SOA 记录。

## 5. 配置 HTTPS

正式实验必须使用 HTTPS，否则浏览器可能拒绝摄像头和麦克风权限。

1. 进入 **域名管理 → mimosa-srtp.com → HTTPS 配置**。
2. 申请或选择能够覆盖 `mimosa-srtp.com` 的证书。
3. 如使用 `www`，证书也应覆盖 `www.mimosa-srtp.com`。
4. 等待证书状态变为已部署或正常。
5. 开启强制 HTTPS。

最终正式地址应为：

```text
https://mimosa-srtp.com
```

## 6. DNS 与上线验收

DNS 生效可能需要几分钟到数小时。可以在 PowerShell 检查：

```powershell
nslookup mimosa-srtp.com
```

生效后使用无痕窗口访问并验收：

- `https://mimosa-srtp.com/`
- `https://mimosa-srtp.com/?study=1`
- `https://mimosa-srtp.com/?research=1`

三类入口用途：

| 使用者 | 链接 | 用途 |
|---|---|---|
| 普通展示 | `https://mimosa-srtp.com/` | 展示会议与 Mimosa，不显示实验记录 |
| 正式参与者 | `https://mimosa-srtp.com/?study=1` | 正式实验与本地日志导出 |
| 研究观察员 | `https://mimosa-srtp.com/?research=1` | 不参与互动的观察、误触发撤销、实验标记与集中日志下载 |

不得把 `?research=1` 发给正式实验参与者。

## 7. 多人上线验收

正式使用前至少用四个参与者会话和一个研究观察会话验证，并额外加入第 5、6 位参与者测试动态扩展：

1. 至少四名参与者与一名观察员进入同一个房间，两类人数分开显示。
2. 第 5、6 位参与者加入后，人数、角色确认、匿名汇总和公开状态正常增长。
3. 摄像头和麦克风权限正常。
4. 手动标记开放问题可进入正式轮次。
5. 真实发言后连续安静约 8 秒可出现私密角色确认。
6. 一人认领等待者，其他成员的角色互不覆盖。
7. 多名回应者可以提交线索，等待者收到动态匿名精确计数。
8. 阳光、浇水和云层能够协调共存并自然进退。
9. 关怀行动能够同步给全体成员。
10. “这次我先不参与”只关闭本人入口。
11. 暂存问题对全员可见；任一当前成员均可认领、编辑并带回，也可二次确认后清理失效问题。
12. 清理后所有在线页面同步移除，刷新或重新进入会议后不会恢复该问题。
12. 观察端可集中收齐所有在线参与者日志，本地导出可作为备用。

## 8. 正式实验操作

### 实验前

1. 为每组指定唯一房间名，例如 `G03-task1`。
2. 把 `https://mimosa-srtp.com/?study=1` 和房间名发给参与者；把同一房间名和 `?research=1` 发给指定研究者。
3. 建议使用实验编号而非真实姓名作为显示名。
4. 检查所有设备能访问 HTTPS 域名并授权摄像头、麦克风。
5. 准备受限的日志收集目录。

### 实验中

- 成员正常进行协作任务；
- 任意成员提出开放问题并等待回应时，可手动标记开放问题；
- 系统也可能在真实发言后持续安静约 8 秒时弹出私密角色确认；
- 实验负责人不替参与者选择角色或回应；
- 研究者使用观察入口并保持闭麦，不参与任务讨论或互动选择；
- 网络中断、误触发、设备权限和成员离开等异常应写入观察笔记。

### 实验结束

1. 参与者不要立即刷新或关闭页面。
2. 研究观察端标记实验结束并点击“向参与者收集日志”。
3. 核对收到数等于在线参与人数，不包含观察员。
4. 点击“下载汇总日志”保存聚合 JSON。
5. 未成功回传的参与者展开“实验记录”，手动导出本地 JSON 作为备用。
6. 将日志保存到仅研究团队可访问的位置。

JaaS 和腾讯云不会替研究团队持久化这些 Mimosa 事件日志。集中收集要求参与者页面仍在线；若提前关闭页面，研究人员无法从腾讯云后台恢复该浏览器尚未交付的本地日志。

## 9. 后续更新网站

以后更新代码时，不需要重新绑定域名：

1. 在本地完成测试和生产构建。
2. 重新生成扁平化的 `mimosa-cloud.zip`。
3. 打开腾讯云原 `mimosa-srtp` 项目，不重复创建新项目。
4. 选择创建新部署、重新部署或上传新资产。
5. 上传新 ZIP 并选择生产环境。
6. 先用预览地址完成多人及研究观察端验收。
7. 验收通过后发布生产部署。
8. 检查 `mimosa-srtp.com` 仍关联生产环境，HTTPS 证书正常。
9. 分别复查 `/`、`/?study=1` 和 `/?research=1`。

自定义域名会继续指向该项目最新成功的生产部署，通常无需重新设置 DNS。

## 10. 常见问题

### 上传时提示非法字符

- 删除页面中已选中的旧 ZIP；
- 刷新创建或部署页面；
- 只上传 `mimosa-cloud.zip`；
- 不要把兼容包解压后再用带中文目录的软件重新压缩。

### 部署后只有预览地址

说明当前部署尚未作为生产环境与自定义域名关联。进入域名管理，将 `mimosa-srtp.com` 关联到生产环境，并完成归属验证、CNAME 与 HTTPS 配置。

### 页面能打开但无法入会

- 确认使用 HTTPS；
- 检查摄像头和麦克风权限；
- 确认所有人使用相同房间名；
- 检查 JaaS 项目状态和额度；
- 使用 `?research=1` 检查观察端连接和集中日志状态。

### 自动沉默没有触发

- 系统必须先观察到一次未闭麦的真实发言；
- 此后房间需要持续安静约 8 秒；
- 所有人闭麦时，环境声不会被当作会议发言；
- 自动感知失败时仍可手动标记开放问题。

### 参与者看不到暂存种子

- 确认所有人使用同一部署版本并重新进入同一房间；
- 晚加入成员会向房间请求当前共享状态；
- 当前系统没有服务器持久化；所有旧成员离开且浏览器本地数据被清除后，腾讯云无法恢复种子。

## 11. 更换团队 JaaS App ID

正式实验如需更换为团队共同管理的 JaaS 项目，在源码目录构建：

```powershell
$env:VITE_JAAS_APP_ID='vpaas-magic-cookie-团队项目ID'
$env:VITE_RESPONSE_COUNT_MODE='exact'
npm ci
npm run test
npm run build
```

随后使用项目脚本重新生成 `mimosa-cloud.zip`。只能把 App ID 放进 `VITE_*`；不得把 API Secret、JWT 私钥或私钥文件放入前端、源码仓库或部署包。
